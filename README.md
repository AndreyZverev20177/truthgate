# Truthgate

**Автономный ИИ-охотник за уязвимостями, который не отправляет в отчёт ложные срабатывания.**

Truthgate ищет уязвимости на веб-приложениях от имени пентестера / bug-bounty
хантера — но, в отличие от обычных ИИ-сканеров, не пересылает в платформу
«галлюцинации» LLM. Каждая найденная уязвимость проходит **детерминированный
proof gate** — независимый машинный код, который либо воспроизводит атаку, либо
отбрасывает находку. В отчёт уходит только то, что доказано.

---

## Проблема, которую решаем

Рынок bug-bounty за 2023–2026 захлестнула волна «ИИ-репортов»: агенты на LLM
генерируют красивые отчёты об уязвимостях, которых не существует. HackerOne,
Bugcrowd и Intigriti публично сообщают, что до **40–70 %** входящих репортов
от новых аккаунтов — false positives или дубликаты. Реакция платформ:

- Пороги на принятие репортов от новых хантеров.
- Штрафы за spam-репорты (снижение сигнала, бан аккаунтов).
- Ручной триаж стал бутылочным горлышком — платформы платят человеко-часы
  на разбор мусора.

Для хантера это значит: **обычный ИИ-сканер приносит убыток**, а не доход —
токены LLM тратятся, репорты отклоняются, репутация аккаунта падает.

Для security-команды, покупающей автоматизированный пентест: **невозможно
доверять отчёту** — каждую находку всё равно нужно верифицировать вручную.

## Наше решение

Truthgate стоит на инженерном принципе:

> **ИИ находит — детерминированный код решает.**

Продукт разделён на три слоя. Один слой (LLM-агент) **придумывает** гипотезы
об уязвимостях. Второй слой (15+ детерминированных валидаторов) **проверяет**
каждую гипотезу воспроизводимым эксплойт-примитивом. Третий слой (proof gate)
принимает финальное решение по **машинному артефакту** — а не по красивому
тексту, который написал LLM.

Результат: в отчёт уходит только то, что можно **повторно доказать за один
клик**. Ложные срабатывания отсекаются до отправки в платформу.

## Что это даёт бизнесу

Для **хантера на bug-bounty платформе**:

- Средний payout за принятую находку на HackerOne — **$500–2 500** (medium),
  **$5 000–15 000** (critical). Отклонённый репорт = 0.
- Один принятый репорт окупает **месяц работы LLM** (~$500–1 000 API-затрат
  при активной охоте). Разница между «5 % accepted» и «40 % accepted» —
  разница между убыточной автоматизацией и прибыльным бизнесом.
- Автоматизация 24/7 на 20–50 in-scope программах одновременно вместо ручного
  скана одной программы за раз.

Для **корпоративной security-команды** (позже, в M8+):

- Снижение цены continuous-пентеста в 3–5 раз (нет ручного триажа галлюцинаций).
- Прозрачный аудит: каждая находка приходит с воспроизводимым артефактом
  (HTTP-запрос, OOB-callback лог, extracted-маркер) — QA может нажать
  «повторить» и увидеть тот же результат.
- Единая методология «до → изменение → после → дельта»: security-команда
  видит, стал ли инструмент лучше после каждого апдейта.

## Как это работает (в одном абзаце)

Truthgate получает цель (in-scope домен bug-bounty программы), LLM-агент
исследует поверхность и выдвигает гипотезы («тут может быть SQL-инъекция в
параметре `id`»). Каждая гипотеза — не находка, а **кандидат**. Дальше
детерминированный валидатор класса SQL-инъекции пытается воспроизвести атаку
с контрольным сравнением (payload TRUE vs FALSE, ответ должен различаться).
Только если отличается — гипотеза становится **находкой**. Если ещё и
OOB-сервер получил callback с уникальным токеном — находка получает высший тир
доказательства (`live`) и попадает в очередь на отправку в платформу.

## Классы уязвимостей в MVP (M1–M2)

15 классов первой волны: SQL-инъекции, SSRF, IDOR/BOLA, SSTI, JWT-баги, LFI,
NoSQL-инъекции, command injection, mass assignment, open redirect, XXE, XSS,
BFLA, prompt injection, excessive agency в LLM-приложениях.

Расширение к M7 (для bounty-экономики): SSRF в cloud-metadata (AWS/GCP/Azure),
deserialization-RCE, HTTP request smuggling, race conditions, OAuth/SSO
misconfiguration, GraphQL-specific, cache poisoning, subdomain takeover.

## Статус и дорожная карта

| Веха | Что делает | Бизнес-смысл | Статус |
|------|------------|---------------|--------|
| **M0** | Каркас, инфраструктура, контракты типов | Фундамент, на котором можно инкрементально собирать продукт без переписываний | **✅ готово** |
| M1 | 6 базовых валидаторов + anti-FP | Первые платящие классы (SQLi, SSRF, IDOR) — можно пробовать на реальных программах | 3 недели |
| M2 | Ещё 9 валидаторов | Полное покрытие MVP-классов | 3–4 недели |
| M3 | Proof gate v2 (судья по артефакту) | Ноль галлюцинаций в отчётах | 1.5 недели |
| M4 | Consensus + sellable-gate | Автоматизированное «отправлять / не отправлять» | 1 неделя |
| M5 | LLM-мозг + рой воркеров | Автономный режим 24/7 | 3 недели |
| M6 | Маховик из 32 CTF-задач | Метрика «стал лучше или хуже» после каждого изменения | 2.5 недели |
| M7 | Интеграции HackerOne/Bugcrowd/Intigriti + автоотчёты | Кнопка «отправить в платформу» | 1.5 недели |
| M8 | Свой OAST-сервер, KMS, аудит | Продакшн-режим, готов к продаже security-командам | 1 неделя |
| M9 | Полировка, публичные бенчмарки | Продукт | 1 неделя |

**MVP (M0–M6):** 4–5 месяцев соло, ~750 часов.
**Продукт (M0–M9):** 6 месяцев соло.

## Экономика запуска (в продакшене)

| Статья | Сумма /мес |
|--------|-----------|
| Хостинг (Hetzner: оркестратор + бенч-раннер + OAST) | ~€50 |
| LLM API (Claude Sonnet / GPT-4.1) при 30–50 прогонах/день | $400–1 000 |
| Домен, TLS | ~$2 |
| **Итого runtime** | **≈ $500–1 100 /мес** |

Целевая окупаемость: **1 accepted critical-репорт в месяц** (~$5 000) окупает
затраты в 5× и выше. Пороговая метрика успешности продукта — **средняя
доля accepted-репортов ≥ 30 %** (при рыночном baseline 10–20 % для ручного
хантера и 5–10 % для ИИ-сканеров).

## Что Truthgate НЕ делает

Чтобы избежать завышенных ожиданий:

- Не заменяет ручного пентестера в комплексных цепочках (chain-of-vulns,
  privilege escalation через 5 шагов).
- Не работает вне in-scope контура — hard-gate на любой out-of-scope запрос.
- Не выполняет деструктивных действий по умолчанию (режим reachability + canary,
  боевые примитивы включаются вручную per-target).
- Не эксплуатирует уязвимости за пределами доказательства достижимости — вывод
  данных ограничен маркером-канарейкой.

## Правовая рамка

Работает **только в авторизованном контуре**: in-scope bug-bounty программы,
собственные стенды, письменные договоры на пентест. Каждый исходящий сетевой
запрос проходит через scope-checker; попытка обратиться к цели вне scope —
техническая ошибка `ScopeViolation`, запрос не отправляется. User-Agent
Truthgate идентифицирует хантера, чтобы платформа могла атрибутировать
трафик.
